# Wilderness Loadouts

Wilderness Loadouts finds the strongest defensive equipment combination in gear you physically own while accounting for a configurable Wilderness replacement-risk budget.

## Features

- Optimizes for Magic, Overall, Ranged, or Melee Defence; Magic Defence is selected by default.
- Scans physical equippable gear from the bank, inventory, and currently worn equipment; bank placeholders are ignored.
- Supports `0`, `1`, `3`, or `4` protected/core items and a configurable max filler-risk budget, which defaults to `100k`.
- Allows every equipment slot to be Auto, Locked to an owned item, or Empty.
- Enforces two-handed weapon and shield compatibility.
- Shows owned alternatives, defensive stats, replacement costs, and clear reasons when an item cannot be used safely by Auto.
- Creates and refreshes a toggleable virtual Bank Tags layout without moving real bank positions.

## Risk model

Protected/core items are assumed protected for loadout planning; selecting `0` protects none. The max filler-risk budget constrains replacement liability for the unprotected portion of the loadout rather than the value received by a killer. Tradeable equipment uses RuneLite's current market estimate. Supported untradeables use generated exact quest-shop, NPC replacement, or Perdu prices. Current high-tier items physically locked with a Trouver parchment use the conservative 500,000 GP mangling fee for deaths above level 20 Wilderness.

Each owned item has separate protected and unprotected outcomes. Items which are always lost, such as Lunar equipment, cannot consume a protected slot. Known residual losses are still counted when an item is protected; for example, an imbued ring of wealth retains its 50,000 GP imbue loss. The displayed Total Risk combines filler risk with those residual protected-item losses, so it may exceed the max filler-risk setting. Non-monetary burdens such as recharging are shown but are not converted to GP. This remains a planning estimate, not a prediction of the items kept or lost on an actual Wilderness death.

### Unpriced equipment

Physical equippable items are discovered independently of pricing, so an unknown replacement value can no longer make owned gear disappear. Unknown and time-only items are visible in their slot's alternatives with an exclusion reason, but Auto does not treat them as free and they cannot be locked into a calculated loadout. Unlocked Trouver-capable items are likewise excluded under the deep-Wilderness policy. A Trouver item is eligible only when its exact physical ID belongs to Jagex's current high-tier category and shows that a parchment has actually been applied. Legacy locked low-tier IDs such as Fire cape (l), imbued god capes (l), defenders (l), and assemblers (l) remain explicitly excluded.

The committed Trouver table is generated by `scripts/generate_trouver_risk_values.py`. The script joins Jagex's current Trouver categories with RuneLite's generated gameval item IDs and also emits the corresponding unlocked IDs. It records the RuneLite source revision and a semantic hash of the Jagex categories, and refuses incomplete category matches.

Exact replacement values are generated by `scripts/generate_replacement_values.py` from the reviewed rows in `scripts/replacement_values.json`. By default the generator validates every current RuneLite item constant and checks that each item and exact GP value still appear together on its cited OSRS Wiki page before emitting `ExactReplacementValues.java`. The initial coverage includes all Culinaromancer's gloves, Mythical cape, Ring of shadows, the wearable Lunar set, and Explorer's rings.

## Usage

1. Open your bank once per RuneLite session so the plugin can scan owned gear.
2. Open the **Wilderness Loadouts** sidebar panel.
3. Choose a defensive focus, protected/core count, max filler-risk budget, and enabled slots. Results update automatically.
4. Select an equipment slot to lock an alternative, return it to Auto, or force it Empty.
5. Open the bank and select **Show in Bank** to view the generated virtual layout; select **Hide in Bank** to close it. The core Bank Tags plugin is required for this step and can be enabled automatically.

## Development

This repository follows the official [RuneLite external-plugin template](https://github.com/runelite/example-plugin) and targets Java 11.

```text
./gradlew test
./gradlew run
```

The replacement-value generators support `--check` for validating that their committed Java tables are current. Their default checks require network access to the cited authoritative sources.

The `run` task launches a development RuneLite client. Do not use browser or input automation to interact with RuneScape; log in and verify the plugin manually.
